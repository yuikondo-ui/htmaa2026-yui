Ready check: upload anything

You did this in Week 2, so this is a quick check. In the Arduino IDE:

  2. Tools → Port → the XIAO's port. If you don't see one: hold B (BOOT), plug in, release. It shows up as a UF2 drive. Upload once, and the real port appears after that.

// Lesson 0 — green heartbeat
#define PIN_GREEN 16   // XIAO RP2040 RGB LED, green channel

void setup() {
  pinMode(PIN_GREEN, OUTPUT);
}

void loop() {
  digitalWrite(PIN_GREEN, LOW);   // LOW = ON (active-low LED!)
  delay(200);
  digitalWrite(PIN_GREEN, HIGH);  // HIGH = OFF
  delay(800);
}

The XIAO's LED legs are connected to 3.3 V, not ground, so LOW turns it on. Red = 17, green = 16, blue = 25.

Lesson 1 · 10 min · no code

The idea: a pad is a tiny bucket

GoalUnderstand what the code will measure, so the numbers make sense when you see them.

The RP2040 has no "touch" hardware, and there is no touchRead() function for it. The copper pad is just a piece of metal connected to a GPIO pin. The trick is to measure time:

3.3 V │ [ ] internal pull-up resistor (~50–80 kΩ, inside the chip) │ ├──────── GPIO pin ───────── copper pad ▢ ← your finger adds │ "bucket size" ═╧═ the pad's own tiny capacitance (a small bucket)
  1. Empty the bucket: set the pin to OUTPUT + LOW. The pad goes to 0 V.
  2. Open the tap: switch the pin to INPUT_PULLUP. Current trickles in through the internal resistor and the voltage on the pad rises.
  3. Count until full: loop while the pin still reads LOW, adding 1 each pass. When the voltage passes ~2 V (the HIGH level you found in the datasheet), the pin reads HIGH and you stop.

With no finger, the bucket is tiny and fills almost instantly (count ≈ 0–2). With a finger, your body adds capacitance: the bucket is bigger, fills slower, and the count goes up (you saw ~70 in Week 2).

Think first 1. Would a bigger pull-up resistor (smaller tap) make the counts bigger or smaller?
2. You touched the pad through a water bottle in Week 2 and it still worked. Why?
Answers

1. Bigger. A smaller tap fills the same bucket more slowly, so there are more loop passes.
2. The electric field goes through thin plastic. Your finger and the pad still form a capacitor, just a weaker one, so the count rises less. This is how touch buttons work under glass.

Lesson 2 · 20 min

Read one pad and print a number

GoalTurn Lesson 1 into code for a single pad and watch the number in the Serial Monitor.

We start with the pad on GPIO 3 (the first pin in Quentin's list). Type this in a new sketch:

// Lesson 2 — read one touch pad
#define PAD 3   // GPIO number of one QPad pad

int readPad(int pin) {
  pinMode(pin, OUTPUT);          // 1. empty the bucket
  digitalWriteFast(pin, LOW);
  delayMicroseconds(25);         //    give it time to fully drain

  pinMode(pin, INPUT_PULLUP);    // 2. open the tap

  int count = 0;                 // 3. count until full
  while (!digitalReadFast(pin) && count < 200) {
    count++;
  }
  return count;
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  int value = readPad(PAD);
  Serial.println(value);
  delay(50);                     // ~20 readings per second
}

digitalWriteFast / digitalReadFast are faster versions from the RP2040 (arduino-pico) core. A faster loop means finer counts. ! means "not", so !digitalReadFast(pin) means "the pin is still LOW". count < 200 is a safety limit so the loop can never run forever.

Upload, then open Tools → Serial Monitor. Over USB the baud rate setting doesn't matter on the RP2040.

Lesson 3 · 15 min

Threshold: light the LED while touching

GoalTurn a number into a yes/no decision: is the pad touched?

Pick a threshold between your "no touch" and "light fingertip" values from the table. Quentin uses 6. Keep readPad() from Lesson 2 and change the rest:

// Lesson 3 — touch = green LED on
#define PAD 3
#define PIN_GREEN 16
#define THRESHOLD 6        // ← your choice, from your table

// ... readPad() exactly as in Lesson 2 ...

void setup() {
  Serial.begin(115200);
  pinMode(PIN_GREEN, OUTPUT);
  digitalWrite(PIN_GREEN, HIGH);   // start OFF
}

void loop() {
  int value = readPad(PAD);
  bool touched = value > THRESHOLD;

  if (touched) {
    digitalWrite(PIN_GREEN, LOW);  // ON
  } else {
    digitalWrite(PIN_GREEN, HIGH); // OFF
  }

  Serial.print(value);
  Serial.print("  touched=");
  Serial.println(touched);
  delay(20);
}

bool holds only true/false. It prints as 1/0.

PredictWhat happens if THRESHOLD is 0? What if it is 150?
You should seeThe LED follows your finger exactly: on while touching, off when you let go.
ChallengeTry both extreme thresholds from your prediction. Then find the smallest threshold that never flickers on by itself, and the largest one that still works with a light fingertip. Any value between them works. Write them down; you'll need this idea in Lesson 6.
What's going on

0: any noise reading of 1 counts as "touched", so the LED flickers or stays on. 150: only a huge press (or never) crosses it, so the LED rarely comes on. A good threshold sits in the gap between the noise and the touch values, which is why you measured them first.

Lesson 4 · 20 min

Press vs. hold: count taps

GoalDetect the moment a finger lands. A button that repeats 50× per second while held is useless for a menu.

"Touched" is a state (true for as long as you hold). A "press" is an event: the one loop where the state changes from false to true. To catch it, remember last loop's state:

wasnowmeaning
falsetruejust pressed (event)
truetrueholding
truefalsejust released (event)
falsefalseidle
// Lesson 4 — count taps, toggle LED on each tap
#define PAD 3
#define PIN_GREEN 16
#define THRESHOLD 6

bool wasTouched = false;   // lives OUTSIDE loop(), so it survives between loops
int taps = 0;
bool ledOn = false;

// ... readPad() as before ...

void setup() {
  Serial.begin(115200);
  pinMode(PIN_GREEN, OUTPUT);
  digitalWrite(PIN_GREEN, HIGH);
}

void loop() {
  bool touched = readPad(PAD) > THRESHOLD;

  if (touched && !wasTouched) {      // just pressed
    taps++;
    ledOn = !ledOn;                    // flip
    digitalWrite(PIN_GREEN, ledOn ? LOW : HIGH);
    Serial.print("tap #");
    Serial.println(taps);
  }

  wasTouched = touched;                // remember for next loop
  delay(20);
}

ledOn ? LOW : HIGH is a short if/else: "if ledOn then LOW, otherwise HIGH". Serial now prints only when something happens, not every loop.

PredictIf you move bool wasTouched = false; inside loop(), what happens?
You should seeOne "tap #n" per tap, however long you hold. The LED toggles like a light switch.
Challenge AAlso print "released after X ms" when you let go. Hint: save millis() on press, and subtract on release.
Challenge BSometimes a single tap counts as 2 (a "bounce" near the threshold). Can you make it happen? Keep this in mind for Lesson 6.
Solution A + answer to the prediction 
unsigned long pressedAt = 0;   // global

// inside loop(), next to the "just pressed" block:
if (touched && !wasTouched) {
  pressedAt = millis();
  // ...
}
if (!touched && wasTouched) {          // just released
  Serial.print("released after ");
  Serial.print(millis() - pressedAt);
  Serial.println(" ms");
}

Prediction: a variable declared inside loop() is created fresh every pass, so it is always false. Every loop while you hold then looks like a new press, and the tap counter races up.

Lesson 5 · 25 min

All six pads + map your board

GoalRead all six pads with one loop, and find out which pin is which physical pad.

The QPad pads are on GPIO 3, 4, 2, 27, 1, 26 (from Quentin's sketch). Instead of six copies of the code, put the pins in an array and loop over it:

// Lesson 5 — all six pads, Serial Plotter friendly
#define N_PADS 6
int padPins[N_PADS] = {3, 4, 2, 27, 1, 26};

// ... readPad() as before ...

void setup() {
  Serial.begin(115200);
}

void loop() {
  for (int i = 0; i < N_PADS; i++) {
    Serial.print("p");
    Serial.print(i);
    Serial.print(":");
    Serial.print(readPad(padPins[i]));
    Serial.print(" ");
  }
  Serial.println();
  delay(30);
}

The p0:12 p1:0 … format gives each line a name in the Serial Plotter, so you get six labelled coloured lines.

You should seeSix lines in the Plotter. Touch one pad at a time, and exactly one line should rise.

Lesson 6 · 30 min

Make it reliable: calibrate + hysteresis

GoalFix the two real-world problems: every pad (and every day) has a different baseline, and readings near the threshold flicker.

Problem 1: one fixed number doesn't fit every pad

Look at your Plotter: the untouched values aren't all identical, and they change if you plug into a different laptop or hold the USB cable. Calibration means that at startup, while nobody touches the board, you measure each pad's resting value (its baseline) and detect touches relative to it.

Problem 2: flicker at the edge

If the reading hovers around 6, it goes 5, 7, 6, 7, 5… and you get several "presses" from one touch (Lesson 4, Challenge B). Hysteresis uses two thresholds: a high one to start a touch and a lower one to end it. In the gap between them nothing changes, just like a thermostat.

count │ ___________ ON├─ ─ ─ ─ ─ /─ ─ ─ ─ ─ ─\─ ─ ─ ─ rise above ON → touched = true │ / \ OFF├ ─ ─ ─ ─/─ ─ ─ ─ ─ ─ ─ ─\─ ─ ─ fall below OFF → touched = false │________/ \______ (in between: keep whatever it was) └──────────────────────────────── time
// Lesson 6 — calibrated + hysteresis, six pads
#define N_PADS 6
#define PIN_GREEN 16
int padPins[N_PADS] = {3, 4, 2, 27, 1, 26};

#define ON_MARGIN  8   // must rise this far above baseline to START a touch
#define OFF_MARGIN 3   // must fall below baseline + this to END it

int  baseline[N_PADS];
bool touched[N_PADS];

// ... readPad() as before ...

void calibrate() {
  for (int i = 0; i < N_PADS; i++) {
    long sum = 0;
    for (int k = 0; k < 32; k++) {   // average 32 readings
      sum += readPad(padPins[i]);
      delay(2);
    }
    baseline[i] = sum / 32;
    touched[i] = false;
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_GREEN, OUTPUT);
  digitalWrite(PIN_GREEN, LOW);      // green = "calibrating, hands off!"
  delay(500);
  calibrate();
  digitalWrite(PIN_GREEN, HIGH);
}

void loop() {
  for (int i = 0; i < N_PADS; i++) {
    int v = readPad(padPins[i]) - baseline[i];   // relative to rest

    if (!touched[i] && v > ON_MARGIN) {
      touched[i] = true;
      Serial.print("pad "); Serial.print(i); Serial.println(" DOWN");
    } else if (touched[i] && v < OFF_MARGIN) {
      touched[i] = false;
      Serial.print("pad "); Serial.print(i); Serial.println(" up");
    }
  }
  delay(10);
}

Keep your hands off while the green LED is on at startup. If you touch during calibration, that pad's baseline will be too high. Press the R (reset) button to recalibrate.

PredictWhat goes wrong if you hold a pad while the board starts up?
You should seeExactly one DOWN and one up per touch, even with slow, light, wobbly touches.
Challenge ATest it: hold a finger on pad 0 and press reset. What happens to pad 0 afterwards? Explain it using the word "baseline".
Challenge B (stretch)Baselines drift slowly (temperature, humidity). While a pad is not touched, let its baseline follow the reading a little each loop: baseline[i] += (raw - baseline[i]) / 16;. Why must you only do this while it's untouched?
Answers

A: The baseline is recorded with your finger on the pad, so it's high. Once you let go, the reading is below the baseline (negative), and a normal touch only brings it back up to about "zero", which never passes ON_MARGIN. The pad seems dead until you reset again.
B: If it tracked during a touch, a long press would slowly become the new "rest", and the pad would release on its own. This is the "baseline tracking while not touched" note in your kigo-pad README. You've now built Step 2 of that plan.

Lesson 7 · 30–60 min · on your own

Mini project: a direction pad

GoalWrite a sketch mostly by yourself, using your board map from Lesson 5. This is the input layer for the kigo-pad.

Spec:

  • Four pads act as UP / DOWN / LEFT / RIGHT, based on where they actually are on your board.
  • A fifth pad is SELECT, and the sixth is MODE.
  • Each tap prints its name once to Serial, e.g. RIGHT.
  • Keep a position x (0–71) and y (0–6), like the 72 kō × 7 categories grid. LEFT/RIGHT change x, UP/DOWN change y. Print x,y after each move.
  • x wraps around (71 → 0), and y stops at its edges.
  • Holding SELECT for 0.4 s prints COLLECTED x,y once (a long press).

Suggested steps (test after each one; don't write it all at once):

  1. Start from your Lesson 6 sketch. Add const int UP = …; etc. using your map.
  2. Replace the DOWN print with a switch (i) or an if-chain that prints the direction name.
  3. Add x, y and the movement.
  4. Add the wrap-around with %.
  5. Add the long press using millis() (Lesson 4, Challenge A).
Hint: wrap-around without negative numbers 
x = (x + 1) % 72;        // RIGHT
x = (x + 71) % 72;       // LEFT  (adding 71 is "−1" that never goes below 0)
if (y > 0) y--;          // UP, stops at the edge
if (y < 6) y++;          // DOWN
Hint: long press that fires only once 
unsigned long selectSince = 0;
bool collected = false;

// when SELECT goes DOWN:  selectSince = millis(); collected = false;
// every loop, while touched[SELECT]:
if (touched[SELECT] && !collected && millis() - selectSince > 400) {
  collected = true;
  Serial.print("COLLECTED "); Serial.print(x); Serial.print(","); Serial.println(y);
}

SymptomLikely cause → fix
